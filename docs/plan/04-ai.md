# 04 — AI features

**Principle:** use AI where it's **personal or creative** (coaching, original
texts, topic content). Use plain code where it's **deterministic** (metrics, bots,
anti-cheat, word drills). AI never runs in the race hot path, and every AI feature
has a non-AI fallback.

## 1. Provider setup (`apps/server/src/ai/`)

| Item | Decision |
|------|----------|
| SDK | `@anthropic-ai/sdk` (official TypeScript SDK) |
| Default model | **Claude Opus 5.5** (`claude-opus-5-5`), set via `AI_MODEL` env so it can change without a deploy |
| Effort | Set explicitly per feature with `output_config.effort`: `low` for text generation and moderation, `medium` for coach reports (Opus 5.5 defaults to `medium`, so be explicit) |
| Output format | **Structured outputs** (`output_config.format` with a JSON schema), with the parsed result validated again by the zod schema in `packages/shared/contracts/ai.ts` |
| Refusals | Check `stop_reason` before reading content. Enable server-side fallback (`fallbacks: "default"` with beta `server-side-fallback-2026-07-01`) so a declined request is retried automatically on a fallback model. If the final `stop_reason` is still `"refusal"`, use the feature's non-AI fallback |
| Caching | Keep each feature's system prompt and examples byte-stable and mark them with `cache_control`, with volatile data (user stats, topic) after it. Verify with `usage.cache_read_input_tokens`. Note: very short prompts are below the minimum cacheable size, so caching matters mainly for the coach |
| Bulk generation | Nightly text pools use the **Message Batches API** (50% cheaper, asynchronous) from the worker |
| Timeouts & retries | 30 s timeout for interactive calls; SDK retries (2) for 429/5xx; typed error handling (`Anthropic.RateLimitError`, etc.) |
| Logging | Every call writes `AiUsage` (tokens, cache reads, cost, latency, ok). The admin dashboard shows spend per feature per day |
| Kill switch | PostHog feature flag per AI feature + global `AI_ENABLED`. A monthly spend cap (`AI_MONTHLY_BUDGET_USD`) auto-disables non-essential features at 100% and alerts at 80% |
| Privacy | Send only **aggregated typing stats** and topic strings. Never names, emails, contacts, or chat logs. Disclosed in the privacy policy |

> **Cost option (your call):** the plan defaults every feature to Claude Opus
> 5.5 ($4 / $20 per million input/output tokens). High-volume, simple jobs
> (topic text generation, drill sentences, moderation) could instead run on
> **Claude Haiku 5.5** (`claude-haiku-5-5`, $0.10 / $0.50 per million tokens), which
> is about 40× cheaper per token. Switch only if it holds quality on the eval set
> (§5). Because the model is an env var per feature (`AI_MODEL_TEXTGEN`,
> `AI_MODEL_COACH`, `AI_MODEL_MODERATION`), this is a config change, not a code
> change.

## 2. Features

### 2.1 AI Typing Coach (M4)

**What the user sees:** a "Coach" card on `/stats` and after every 10th race. It
contains a short diagnosis ("You're fast on home-row words but lose ~120 ms on
`th`/`he` transitions and on shifted characters"), 3 concrete tips, a 7-day plan
(each day links to a drill), and progress since the last report.

**Input (aggregated, ~1.5–3k tokens):** last 30 days of `UserStatsDaily`; top 15
weakest keys (error rate, latency); top 15 slowest bigrams; WPM/accuracy trend;
accuracy vs speed trade-off curve; mode mix; device; previous report summary.

**Output schema:**
```ts
{
  headline: string;                    // ≤ 120 chars
  diagnosis: string[];                 // 2–4 bullets
  strengths: string[];                 // 1–3
  tips: { title: string; detail: string; drill?: DrillSpec }[];   // exactly 3
  plan: { day: 1..7; focus: string; minutes: number; drill: DrillSpec }[];
  encouragement: string;
}
DrillSpec = { kind: 'keys' | 'bigrams' | 'words' | 'punctuation' | 'numbers' | 'accuracy'; targets: string[]; durationSec: 30|60|120 }
```

**Rules:** the coach must only cite numbers present in the input. A post-check
verifies each number in the output appears in the input, and regenerates once if
not. Reports are cached until ≥ 10 new accepted races. Quota: Free 1/week,
Pro 30/month (fair use; keeps the AI cost per Pro user within the §4 guardrail).

**Fallback:** a rule-based report (template + the same `DrillSpec`s computed
deterministically from weakest keys and bigrams).

### 2.2 Adaptive drills (M4)

- **v1 (deterministic, free):** a weighted word sampler. Words containing target
  keys or bigrams get their weight multiplied, readability stays via real
  dictionary words, and the result is a 30–120 s drill.
- **v2 (AI, Pro):** generates natural sentences that over-represent the targets.
  Output: `{ sentences: string[] }`. A server check confirms target coverage ≥ X%
  and only allowed characters; it falls back to v1 if the check fails.
- After a drill, show per-target improvement versus the user's baseline. This feeds
  the coach's "progress since last report".

### 2.3 Topic texts for rooms (M4)

- Host enters a topic (≤ 80 chars), picks length (short/medium/long) and difficulty.
- Pipeline: **moderate topic** → check cache (`ai:cache:{hash(topic,len,diff,lang)}`) →
  generate `{ title, text }` (original prose, no quotes from real works, no
  real-person claims, ASCII punctuation set by difficulty) → validate (length,
  charset, profanity filter) → **moderate output** → store as a `Text` (`source: ai`).
- Quota: Free 3/day, Pro 50/day. Popular topics end up in the shared pool.
- Fallback: a random curated text with a matching tag, or the general pool.

### 2.4 Code typing texts (M4)

- Curated seed set (~50 per language) plus AI-generated snippets: idiomatic,
  10–25 lines, no external APIs, 2-space indent, ASCII only.
- Validation: lint/parse with a lightweight parser per language where available
  (e.g. `acorn` for JS); reject on failure.
- Generated in nightly batches. Free: JS + Python. Pro: all languages.

### 2.5 Moderation (M3 basic, M4 AI)

- Layer 1 (always, synchronous): normalized keyword/regex filter (leetspeak folding)
  for handles, display names, room names, chat, custom text, and topics.
- Layer 2 (AI, async or on-demand): borderline items from layer 1, plus all
  AI-generated and custom texts shared in public contexts. Output:
  `{ allowed: boolean; categories: string[]; reason: string }`.
- Chat is rate-limited, with per-user mute and report. Reports go to `ModerationFlag`.

### 2.6 Bot personas (M4)

Pre-generate ~200 bot personas (name, avatar, style, 10 lobby lines, 5 win/lose
emotes) in one batch. Personas are static JSON with no live calls, so they cost
nothing per race.

### 2.7 Learn-while-typing packs (M6, Pro/cosmetic upsell)

Curated + AI-generated themed packs (exam vocabulary, language learning with
translations, fun facts with a 3-question quiz after the race). Generated in
batches, reviewed by an admin before publishing.

### 2.8 Ask your stats (M6, Pro)

Natural-language questions over the user's own stats ("When do I type fastest?").
Claude gets **tool definitions for pre-defined, parameterized queries** (stats by
hour of day, by mode, trend over range). It never gets raw database access. The
answer is rendered with a small chart when a tool returned a series.

## 3. Prompt management

- Prompts live in `apps/server/src/ai/prompts/{feature}.v{N}.ts`. Each one
  exports `system`, `buildUserContent(input)`, `outputSchema`, and `promptVersion`.
- `promptVersion` is stored with every output (`CoachReport`, `Text.ai`), so you
  can compare versions.
- Prompts are written plainly and specifically: what the output is for, who reads
  it, the length limits, and what to avoid. No role-play fluff.

## 4. Cost model (estimates, to be verified against real usage)

At Opus 5.5 list prices ($4 input / $20 output per million tokens), before caching
and batch discounts. Adaptive thinking tokens are billed as output, so real costs
run somewhat higher than these figures. **Measure with `AiUsage` in staging before
setting final quotas.**

| Feature | Tokens per call (in / out) | ≈ Cost per call | Volume assumption | ≈ Monthly at 5k MAU |
|---------|---------------------------|-----------------|-------------------|---------------------|
| Coach report | 3,000 / 1,000 | $0.03 | 30% of MAU × 3 reports | ~$135 |
| Topic text | 400 / 500 | $0.012 | 2k/month (after cache hits) | ~$24 |
| AI drill (Pro) | 300 / 400 | $0.009 | 300 Pro × 20 | ~$54 |
| Nightly pools (batch, −50%) | — | — | 1,500 texts/month | ~$10 |
| Moderation (AI layer) | 300 / 60 | $0.0024 | 10k/month | ~$24 |

Guardrail: **AI cost per Pro subscriber must stay under 15% of the subscription
price.** If it doesn't, tighten quotas, use more caching, or switch high-volume
features to Haiku 5.5 (see the cost option above).

## 5. Evaluation

Before enabling any AI feature in production:
- **Golden sets** in `apps/server/test/ai-evals/`: 30 synthetic stat profiles for
  the coach, 50 topics (including adversarial ones) for text generation, and 100
  moderation cases (allowed and disallowed).
- **Automated checks:** schema validity 100%; coach numeric-grounding check ≥ 98%;
  topic texts pass length, charset, and moderation ≥ 97%; moderation precision and
  recall on the labeled set ≥ 95%.
- **Human review:** read 20 coach reports and 30 texts per prompt version.
- Run evals in CI **manually** (`pnpm eval:ai`). They cost money, so they never run
  on every PR.
